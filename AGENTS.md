# AGENTS.md

## Project Name

AI Conversation Replay Demo

## Project Overview

Build a frontend demo application for **AI Conversation Replay**, a system that allows call center users such as supervisors, QA reviewers, trainers, and agents to review an audio conversation without listening to the entire call from beginning to end.

The application must:

1. Play a call recording directly in the web browser.
2. Display AI-generated conversation replay events.
3. Allow the user to click an event and automatically seek the audio player to that event's `startSec`.
4. Play only the selected event range from `startSec` to `endSec`.
5. Visually show the active replay event while audio is playing.
6. Display a call summary generated by an LLM.
7. Work as a self-contained demo using mock JSON data and a local/static audio file.

This project is a frontend demo. Do not build a production backend unless explicitly requested.

---

# 1. Primary Goal

Create a polished and easy-to-understand demo that demonstrates this user journey:

```text
Call Recording
      ↓
Transcript / LLM Processing
      ↓
Call Summary
      ↓
Replay Events
      ↓
User selects an event
      ↓
Audio jumps to startSec
      ↓
Audio plays until endSec
```

The main value of the demo is that a reviewer can immediately listen to important moments identified by AI.

Examples:

- Customer explains the main problem
- Agent verifies customer information
- Agent proposes a solution
- Customer becomes dissatisfied
- Agent escalates the case
- Agent closes the conversation

# 8. Replay Event Playback Behavior

This is a critical requirement.

When the user clicks a replay event:

```text
ReplayEvent.startSec = 126.8
ReplayEvent.endSec   = 167.2
```

The player must:

1. Seek to `126.8`.
2. Start playback automatically.
3. Continue playing.
4. Stop or pause when playback reaches `167.2`.
5. Keep that event highlighted while it is playing.

Pseudo logic:

```ts
function replayEvent(event: ReplayEvent) {
  selectedEvent.value = event;

  audio.currentTime = event.startSec;
  audio.play();
}
```

During playback:

```ts
if (
  selectedEvent &&
  audio.currentTime >= selectedEvent.endSec
) {
  audio.pause();
}
```

Because browser timing callbacks are not perfectly exact, small timing tolerance is acceptable.

Recommended tolerance:

```ts
const END_TOLERANCE_SEC = 0.1;
```

Do not create multiple unmanaged `timeupdate` listeners.

Use Vue lifecycle hooks such as `onMounted` and `onBeforeUnmount` for cleanup correctly.

# 9. Optional Replay Buffer

For natural listening, support optional pre-roll and post-roll.

Default:

```ts
const PRE_ROLL_SEC = 1;
const POST_ROLL_SEC = 0.5;
```

Actual playback:

```ts
const playbackStart = Math.max(
  0,
  event.startSec - PRE_ROLL_SEC
);

const playbackEnd = Math.min(
  audioDuration,
  event.endSec + POST_ROLL_SEC
);
```

The UI must continue showing the original AI timestamps.

Pre-roll and post-roll affect only playback.

# 17. Time Formatting

Create a reusable utility.

```ts
export function formatTime(seconds: number): string {
  const totalSeconds = Math.floor(seconds);

  const minutes = Math.floor(totalSeconds / 60);
  const secs = totalSeconds % 60;

  return `${String(minutes).padStart(2, "0")}:${String(
    secs
  ).padStart(2, "0")}`;
}
```

# 26. Replay State Logic

There are two playback modes.

## Normal Playback

The user manually presses Play.

Behavior:

```text
Play until audio ends or user pauses.
```

No replay end boundary is active.

---

## Replay Event Mode

The user selects an AI event.

Behavior:

```text
Seek to event start
↓
Play
↓
Pause at event end
```

When the user manually seeks elsewhere while replay mode is active:

Recommended behavior:

```text
Cancel replay event mode
Continue as normal playback
```

This avoids surprising automatic pauses.

---

type PlaybackMode =

# 28. LLM Integration Boundary

The frontend must NOT call an LLM directly for the first demo.

Assume the LLM has already produced:

```json
{
  "callSummary": {},
  "replayEvents": []
}
```

The frontend consumes the JSON result.

Design the code so it can later replace:

```ts
import { demoCall } from "./data/demoCall";
```

with:

```ts
const result = await fetch(
  `/api/conversation-replay/${callId}`
);
```

Do not tightly couple UI components to mock data.

# 33. Coding Guidelines

- Use TypeScript strictly.
- Prefer small reusable Vue Single-File Components.
- Avoid `any`.
- Avoid duplicated event-playing logic.
- Keep timestamp calculations in utilities/composables.
- Clean up all wavesurfer and audio event listeners.
- Avoid unnecessary global state.
- Avoid premature backend implementation.
- Avoid hard-coded DOM queries.
- Do not mutate demo data.
- Use meaningful names.
- Add comments only when logic is non-obvious.
- Prioritize reliability over excessive animation.
